# Cybersecurity Compendium: 50 Essential Terms

| No. | Acronym | Full Term | Definition & MSc Context |
| :--- | :--- | :--- | :--- |
| 1 | **AES** | Advanced Encryption Standard | A symmetric block cipher chosen by the U.S. government to protect classified information. |
| 2 | **APT** | Advanced Persistent Threat | A sophisticated, long-term network attack where an intruder gains access to a network and stays undetected. |
| 3 | **BCP** | Business Continuity Planning | The process of creating systems of prevention and recovery to deal with potential threats to a company. |
| 4 | **BYOD** | Bring Your Own Device | A policy allowing employees to use personal devices for business purposes, increasing the attack surface. |
| 5 | **C&C** | Command and Control | The infrastructure (servers/software) attackers use to send instructions to compromised systems (botnets). |
| 6 | **CA** | Certificate Authority | A trusted entity that issues digital certificates to verify identities on the internet. |
| 7 | **CIA** | Confidentiality, Integrity, Availability | The "Triad" model designed to guide policies for information security within an organisation. |
| 8 | **CISO** | Chief Information Security Officer | The senior-level executive responsible for establishing and maintaining the enterprise vision and strategy. |
| 9 | **CVE** | Common Vulnerabilities and Exposures | A list of publicly disclosed computer security flaws, each assigned a unique ID (e.g., CVE-2024-XXXX). |
| 10 | **DDoS** | Distributed Denial of Service | An attempt to make an online service unavailable by overwhelming it with traffic from multiple sources. |
| 11 | **DLP** | Data Loss Prevention | A strategy for making sure that end users do not send sensitive or critical information outside the corporate network. |
| 12 | **DORA** | Digital Operational Resilience Act | A EU regulation strengthening the IT security of financial entities (Critical for SRM modules). |
| 13 | **DRP** | Disaster Recovery Plan | A documented process or set of procedures to execute an organisation's response to a disaster. |
| 14 | **EDR** | Endpoint Detection and Response | Technology that continually monitors endpoints to mitigate malicious activities. |
| 15 | **GRC** | Governance, Risk, and Compliance | A strategy for managing an organisation's overall governance, enterprise risk management, and compliance with regulations. |
| 16 | **HIDS** | Host-based Intrusion Detection System | An application that monitors a computer or network for suspicious activity. |
| 17 | **IAM** | Identity and Access Management | A framework of policies and technologies to ensure that the right users have the appropriate access to technology resources. |
| 18 | **IDS** | Intrusion Detection System | A device or software application that monitors a network or systems for malicious activity or policy violations. |
| 19 | **IPS** | Intrusion Prevention System | A network security tool that monitors network traffic and has the power to stop/block detected incidents. |
| 20 | **ISMS** | Information Security Management System | A set of policies and procedures for systematically managing an organisation's sensitive data (e.g., ISO 27001). |
| 21 | **JWT** | JSON Web Token | An open standard used to share security information between a client and a server. |
| 22 | **KRI** | Key Risk Indicator | A metric used to measure the likelihood that a combined risk event will exceed the organisation's risk appetite. |
| 23 | **LEAP** | Lightweight Extensible Authentication Protocol | A proprietary version of EAP used in wireless networks. |
| 24 | **MFA** | Multi-Factor Authentication | A security system that requires more than one method of authentication from independent categories of credentials. |
| 25 | **MITM** | Man-In-The-Middle | An attack where the attacker secretly relays and possibly alters the communications between two parties. |
| 26 | **MTTD** | Mean Time To Detect | The average amount of time it takes for an organisation to become aware of a potential security incident. |
| 27 | **MTTR** | Mean Time To Respond | The average time it takes to neutralise a threat once it has been detected. |
| 28 | **NGFW** | Next-Generation Firewall | A part of third-generation firewall technology, combining a traditional firewall with other network device filtering functions. |
| 29 | **NIST** | Nat. Institute of Standards & Tech | A non-regulatory agency that promotes innovation and industrial competitiveness, famous for its Cybersecurity Framework. |
| 30 | **OSINT** | Open-Source Intelligence | Data collected from publicly available sources to be used in an intelligence context. |
| 31 | **OT** | Operational Technology | Hardware and software that detects or causes a change, through the direct monitoring and/or control of industrial equipment. |
| 32 | **PaaS** | Platform as a Service | A cloud computing model where a third-party provider delivers hardware and software tools to users over the internet. |
| 33 | **PAM** | Privileged Access Management | Cybersecurity strategies and technologies for exerting control over the elevated access and permissions for users. |
| 34 | **PCI DSS** | Payment Card Industry Data Security Standard | An information security standard for organisations that handle branded credit cards. |
| 35 | **PII** | Personally Identifiable Information | Any data that could potentially identify a specific individual. |
| 36 | **PKI** | Public Key Infrastructure | A set of roles, policies, and procedures needed to create, manage, distribute, use, store, and revoke digital certificates. |
| 37 | **RBAC** | Role-Based Access Control | A method of restricting network access based on the roles of individual users within an enterprise. |
| 38 | **RPO** | Recovery Point Objective | The maximum amount of data (measured by time) that can be lost before causing significant harm to the business. |
| 39 | **RTO** | Recovery Time Objective | The duration of time within which a business process must be restored after a disaster. |
| 40 | **SASE** | Secure Access Service Edge | A network architecture that rolls SD-WAN and security into a cloud-native service. |
| 41 | **SDLC** | Software Development Life Cycle | A process for planning, creating, testing, and deploying an information system (critical for DevSecOps). |
| 42 | **SIEM** | Security Info & Event Management | A solution that provides real-time analysis of security alerts generated by applications and network hardware. |
| 43 | **SLA** | Service Level Agreement | A commitment between a service provider and a client regarding the level of service (uptime, response time). |
| 44 | **SOC** | Security Operations Center | A centralised unit that deals with security issues on an organisational and technical level. |
| 45 | **SSO** | Single Sign-On | An authentication scheme that allows a user to log in with a single ID and password to any of several related systems. |
| 46 | **TLS** | Transport Layer Security | A cryptographic protocol designed to provide communications security over a computer network (successor to SSL). |
| 47 | **TTPs** | Tactics, Techniques, and Procedures | Describes the behaviour or "style" of an actor or group of actors in a cyberattack. |
| 48 | **VPN** | Virtual Private Network | Extends a private network across a public network, allowing users to send/receive data as if they were directly connected. |
| 49 | **WAF** | Web Application Firewall | A specific form of application firewall that filters, monitors, and blocks HTTP traffic to and from a web application. |
| 50 | **ZTNA** | Zero Trust Network Access | A category of technologies that provides secure remote access to applications based on clearly defined access control policies. |
